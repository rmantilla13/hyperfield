# Changelog

## 0.2.0 (unreleased)

Everything added since the first build (0.1.0). Measurements and implementation notes follow under "Details".

- **Stage**: block a shot in 3D (boxes, figures, walls, .glb models, a camera path and a lens) and render it with the LTX-2.5 Layout-to-Render IC-LoRA. Look frames come from Z-Image Turbo on the depth pass. Object takes place into the set as props. MCP `stage_render`.
- **Object**: one still to a textured GLB on TRELLIS.2, with a turntable, a three.js viewer, Make 3D on any still and a 3D library filter. MCP `make_3d`.
- **Director**: genres, an era scrubber from 1960 to 2020 graded on the output, and speed ramps.
- **Scene**: a written scene becomes a 2 to 6 shot list from a local LLM, rendered and cut into one take; edit, reorder and re-roll single shots. MCP `direct_scene`.
- **Cast**: save a character, prop or place from pictures and `@mention` it in any prompt; videos hold it on an LTX-2.5 Ingredients reference sheet.
- **Effects**: 11 one-click LoRA effects on clips and stills (Lightricks IC-LoRAs and kabachuha community LoRAs).
- **Edit** and the image apps on Qwen-Image-Edit 2509: New angle, Coverage, Push in, Next beat, Relight, Expand.
- **Mirror**: phone capture by QR code, Depth Anything V2 Small depth mode, Restyle with 22 looks, and an experimental Object swap.
- **Remove background** for stills and clips: BiRefNet, with SAM 3.1 steady and tracked modes and ProRes 4444 alpha output.
- **Extend**, **Transitions**, **Speak** and **Add sound**, all on LTX-2.5 with no new weights.
- **Upscale**: Sharpen (RealESRGAN, optional RIFE frame doubling), Redraw (SeedVR2) and Dream (LTX-2.5), with a drag compare.
- **Seam Doctor**: every loop is measured and badged; "Improve the seam" trims, re-renders or reseeds and reports the result.
- **Finish in HDR**: ACEScg EXR sequence, HLG HEVC and HLG ProRes masters through the LTX-2.5 SDR-to-HDR IC-LoRA, checked on the way out.
- **Your LoRAs**: a LoRA chip on Image (Qwen-Image, FLUX.2) and Video (LTX-2.5, cast sheets included) stacks up to four of your own LoRAs with a strength each. The server reads every file's safetensors header to learn which model it was trained for, offers it only there, and refuses a mismatch with a readable error; task LoRAs (IC-LoRAs, step distills) stay out of the menu. MCP `list_loras`.
- **FLUX.2 references**: up to six reference pictures on an Image take, and `@cast` on FLUX.2 now feeds the cast pictures in as FLUX.2 reference latents rather than composing through Qwen-Image-Edit, which keeps photographic skin.
- **Stage look frames** name the blocking figures as real people and soften the depth pass slightly, so a figure stand-in renders as a person, never as its capsule silhouette.
- **Hardening**: the local API refuses requests sent by pages on other sites (Origin check on top of the Host check), project folders stay inside the output folder, Stage and Object load on demand (main bundle 1.2 MB to 477 kB), phone layouts scroll as a page, and a take waiting behind another app's jobs shows "Waiting for the engine" instead of "Rendering".
- **MCP server**: 31 stdio tools drive every app; `npm run mcp:check` pins request bodies to the page code.
- **Open in ComfyUI** and **Download workflow** on every take; API-format workflows committed in `workflows/`.
- Redesigned interface, drag and drop media anywhere, render times recorded from ComfyUI's history.
- Verified third-party license notices; the server refuses non-local hosts and never serves file paths taken from a request.
- Apps gallery: one-sentence blurbs, "New" on Stage, Director, Mirror and Effects, "Top" on Video; Explore leads with Stage.
- Public README, `docs/MEDIA.md` provenance for every sample file.
- 720p by default for every video app on 24 GB or more (480p below), with per-app caps.

## Details

- **Object (image to 3D).** Any still becomes a textured GLB on TRELLIS.2 (bf16, through ComfyUI 0.38's built-in Trellis2 nodes, wired like ComfyUI's own TRELLIS.2 template): BiRefNet cuts the subject out (or the PNG's own alpha is used), DINOv3 conditions a structure, shape and texture pass, then the mesh is remeshed, decimated, UV-unwrapped and baked to PBR textures. Draft is up to 150k faces with 2K maps; High is up to 400k faces with 4K maps plus a baked normal map and AO. The graph also renders a 32-frame turntable mp4 in the engine (the take's poster and hover clip) and keeps the isolated subject next to the GLB. New `/object` app with a three.js viewer (orbit, textured / clay / wireframe), Make 3D on any still in the Viewer, a 3D filter in the Library, MCP `make_3d`, three exported workflows and the `trellis2` bundle (about 14 GB). The GLB is served at `/api/media/<take>` as `model/gltf-binary` for a scene to load. SaveGLB's output is a "3d" UI output the v2 API does not list, so the server reads it from ComfyUI's history; Object needs a local engine for now.
  Measured 10/17 on a 5090 shared with other jobs (render time from ComfyUI's history): Draft 108 s cold (every TRELLIS.2 weight loaded) and 91 s warm, both 48-frame turntables; High 240 s warm without a turntable and 349 s with 48 frames, which is why the turntable is now 32 frames (Draft with 32 frames: 85 s warm). GPU memory peaked at 30.5 of 32.6 GB in every run with other agents' models resident (16 to 30 GB before the job); ComfyUI evicted them as needed and nothing ran out of memory. Draft GLBs are about 10 MB, High about 42 to 45 MB (three 4K PNG maps).
  Quality, judged from turntables and the viewer: a product kettle (High) holds its handle, wire bail, spout and lid knob with clean silhouettes, but the smooth enamel picks up a hammered, dimpled texture that is not in the photo. A full-body cartoon character (Draft) gets a convincing back, backpack and boots; the face is soft and the fingers fuse into mitts. A photo cropped at the neck (a beagle bust) comes back as a bust with a flat cut base and plausible ears, with the eyes rendered red-brown.

- Director: Genre (Drama, Noir, Horror, Action, Comedy, Epic, Sci-fi; picking one fills light, grade, look and camera), an Era scrubber from 1960 to 2020 that names the decade in the prompt and grades the output in the graph (a GLSLShader pass blended between decades), and Speed ramps (Slow-mo, Ramp up, Impact, Bullet time: RIFE in-between frames, then frames picked along a speed curve; ramped shots drop their sound). New Scene mode: a local LLM inside the engine (Gemma 3 12B via TextGenerateLTX2Prompt, Ollama as an optional fallback) turns a scene into a 2 to 6 shot list, each shot renders on LTX-2.5 (optionally from a Qwen hero frame), and a cut graph joins them into one take; edit, reorder and re-roll single shots. MCP `direct_scene`, `direct_shot` gains `genre`, `era`, `era_grade` and `ramp`; four new exported workflows.
- **Seam Doctor.** Every Seamless loop take is measured at its wrap when it lands and carries a badge, Seamless or Visible seam. The score ports SEAM's loop check (8x8 tile means, wrap against the motion right at the loop point) and adds a texture score (mean luma difference per pixel at 416 px), because tile means average away the fine shimmer LTX loops show. Seamless = texture ratio 2.0 or less and composition ratio 1.5 or less (or a wrap too small to see). "Improve the seam" in the Viewer works on any video take and says what happened (for example "Seam improved from 4.1x to 2.8x a frame step" or "No strategy closed this seam; kept the original"); the Loop tab's "Auto-fix the seam" is off by default (and `make_loop` `auto_fix` defaults to false), because the fixes lower the seam far more often than they close it (see the measurements below). The badge is on for every loop. `fix_seam` and `finish_hdr` MCP tools; `make_loop` takes `auto_fix`.
  Fixes, tried in this order and only while the seam still shows: **trim** (the longest window, at least max(2 s, half the clip), that closes on both scores; no GPU), **regen** (rotate the loop so the wrap sits mid-clip, VAE-encode the whole loop, freeze the outer latent frames, re-noise the rest to sigma 0.65 and denoise once on LTX-2.5, rotate back; same length, every frame from one decode), **reseed** (the loop again with a new seed). **bridge** (LTX-2.5 first/last frames from about 1 s before the wrap to about 1 s after, inner frames spliced in place, the flow SEAM used fal for) is kept as a manual strategy. No crossfades.
  Measured 10/17 on five loops at 832x448, wrap ratio as a multiple of a frame step (texture unless marked c = composition):

  | Loop | Before | Trim | Regen 0.35 / 0.5 / 0.65 | Bridge | Reseed |
  | --- | --- | --- | --- | --- | --- |
  | Kite, 5 s | 3.83 | none closes | 2.82 / 2.91 / **2.53** | 5.74 | 4.11 |
  | Stair, 3 s | 7.01 | none closes | 6.42 / 6.27 / **6.18** | 8.81 | 9.73 |
  | Lantern, 4 s | 3.70 | none closes | 3.00 / 3.17 / **2.79** | 2.86 | 3.78 |
  | Dog, 3 s | 2.90 | **1.71 seamless** (64 of 73 frames) | 2.11 / 2.39 / **1.90 seamless** | 2.00 (c 1.87) | 7.67 |
  | Lighthouse, 3 s | 6.38 | none closes | 11.9 c at 0.5 | 24.5, 32.9 native guides, 23.1 at strength 1.0 | |

  Regen at 0.65 lowered the ratio on all four new loops (mean 4.36 to 3.35) and made one seamless; the bridge was worse on two of four and badly worse on the lighthouse; a new seed is a coin toss (mean 6.3). So auto runs trim, then regen at 0.65, then reseed.
  What the measurements say about the shimmer: a VAE round trip moves fine texture by about 2 levels on these clips (ten times an ordinary frame step), so any fix that splices newly decoded frames into the original file creates a new seam where they meet; that is why the bridge fails. Two frames that were neighbors in the loop, decoded at opposite ends of one latent sequence, still differ by about 5x a frame step: the sequence-end decode is most of the wrap shimmer, as suspected. Regen keeps every frame in one decode, which is why it helps, but its own join (frame h, where the rotated clip's ends meet) measures 1.6 to 2.5x, so it moves part of the seam to mid-clip rather than removing it. Raising the loop's guide strength is not the fix (kills motion, per the earlier test) and neither is a bridge at strength 1.0 (23x).
  End to end through the server: a new loop with Auto-fix on (3.11) queued regen (2.25) and then a new seed (2.71) by itself and stopped; Fix the seam on the stair loop ran regen (6.72, another seed) then a new seed (4.80). The doctor stops after the new seed whatever it measures.
  The bridge first used the template's 1536 px guide resize on frames already at the output size; that shifted the bridge 0.18 px against the clip and lit every edge. Guides taken from the clip now skip it (`nativeGuides`).
- **Finish in HDR.** Any video take re-renders through the LTX-2.5 SDR-to-HDR IC-LoRA (a port of Lightricks' template, new `hdr` bundle, scene embeddings in `models/embeddings/`): a 16-bit half ACEScg EXR sequence (zipped, stored), the HLG BT.2020 10-bit HEVC master remuxed to .mov, and a ProRes 422 HQ HLG .mov; the take itself is the tonemapped SDR preview. Clips that are not 8k+1 frames are padded (a loop with its own head, anything else by holding the last frame) and cut back before anything is written. Each finish is checked on the way out: ffprobe for bt2020 / arib-std-b67 / 10-bit and the frame count, the EXR header for half pixels and AP1 chromaticities. Measured on a 5090: 52 s for 3 s (73 frames) and 44 s for a 64-frame clip padded to 65, both 832x448; 1 to 2 s to collect. Output stays locked to the source: best-matching frame offset 0 on every sampled frame, spatial shift 0 px, high-pass correlation 0.83, EXR peaks 1.5 to 6.2 linear with about 1% of pixels over 1.0.
- A job's result now prefers its graph's own save node: a core LoadVideo reports its input as a video output, which the first HDR finish picked up as its result.
- Remove background (`/cutout`, Viewer action, Edit strip, `remove_background` MCP tool): BiRefNet on core ComfyUI nodes. Stills give a transparent PNG or the subject over a color, a blur or a new picture in about 2 s. Clips default to the per-frame matte (the most stable on the test clips); SAM 3.1 adds a steady mode (matte gated to the tracked subject) and a tracked mode and come out as ProRes 4444 with alpha plus an MP4 preview over a checkerboard.
- Mirror > Restyle (`restyle_video`): 22 looks; frame 0 is redrawn with Qwen-Image-Edit and Mirror (depth or edges) carries the clip's motion through it, in one job. Viewer continue-action on any clip.
- Mirror > Object swap (`swap_object`, experimental, hidden behind `?mode=swap`): SAM 3.1 track, Qwen-Image-Edit on a crop around the object in frame 0 pasted back with the mask, LTX-2.5 in/outpainting IC-LoRA through the clip, Laplacian blend back onto the source. Works on objects; a swapped moving person loses the source's action.

- Every job now runs through the Comfy SDK (`@comfyorg/sdk`, Comfy API v2), locally via comfy-api-proxy or on Comfy Cloud.
- MCP server (`npm run mcp`, `docs/MCP.md`): stdio tools drive every app from Claude Code, Claude Desktop or any MCP client, as a thin client of the HTTP API. `npm run mcp:check` pins its request bodies to the page code.
- Extend, Transitions, Speak and Add sound, all on LTX-2.5 with no new weights. Extend continues a take forward (its last second frozen in the AV latent, sound included) or adds a lead-in; Transitions bridges two takes or stills with a first + last frame move in 8 styles and joins them; Speak is audio to video from a face and a sound file (port of the official A2V workflow); Add sound is video to audio with the frames frozen. Viewer continue-actions, MCP tools (`extend_video`, `make_transition`, `speak`, `add_sound`) and exported workflows for each.
